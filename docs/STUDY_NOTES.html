2. 读本项目需要的 C++ 基础

你不需要先成为 C++ 高手。读这个项目时，先掌握下面几个概念就够了。

概念 在本项目里的作用 例子
struct 把一组相关数据放在一起。 Token、Symbol、Quad
class 把数据和操作这些数据的函数放在一起。 Lexer、Parser、SemanticAnalyzer
enum class 定义一组固定类别，避免用数字硬猜。 TokenType::Identifier
std::vector 动态数组，常用来保存 Token、四元式、状态栈。 std::vector<Token>
std::string 字符串，保存标识符名、操作符、错误信息。 token.lexeme
std::unordered_map 哈希表，用于关键字表和符号表。 keywords_、scopes_
读代码技巧：看到 std::vector<Token> 时，把它理解成“Token 列表”。 看到 std::unordered_map<std::string, Symbol> 时，把它理解成“名字到符号信息的表”。

4. Token 是什么

源代码是普通字符串，编译器不好直接理解。词法分析会先把字符串切成 Token。 Token 可以理解为“有类型的单词”。

例子

const a = 10;

会被切成：

const保留字
a标识符
=运算符
10无符号整数
;界符

相关代码：

src/common/Token.h
src/common/Token.cpp

核心结构：

struct Token {
    TokenType type;      // Token 类型
    std::string lexeme;  // 原始文本
    int line;            // 行号
    int column;          // 列号
    std::string error;   // 词法错误信息
};

5. 词法分析 Lexer

相关代码：

src/lexer/Lexer.h
src/lexer/Lexer.cpp

入口函数：

std::vector<Token> Lexer::tokenize();

5.1 Lexer 的整体扫描过程

当前字符
→
空白/注释？
→
字母？
→
数字？
→
运算符/界符？
while (!isAtEnd()) {
    skipWhitespaceAndComments(tokens);

    if (当前字符是字母) {
        scanIdentifier();
    } else if (当前字符是数字) {
        scanNumber();
    } else {
        扫描运算符、界符或非法字符;
    }
}

5.2 标识符和关键字

同样是字母开头，可能是关键字，也可能是普通标识符。

const a = 10;
var b;

const、var 是关键字，a、b 是标识符。

代码里用 keywords_ 表判断：

{"const", TokenType::Const}
{"var", TokenType::Var}
{"procedure", TokenType::Procedure}
...

5.3 数字和非法数字串

课程要求：数字开头后面又接字母，例如 2a，是非法单词。

const 2a = 10;

扫描逻辑是：

  1. 先读连续数字。
  2. 如果后面立刻接字母，就继续读完整串。
  3. 生成 非法字符(串)。

5.4 注释处理

支持两类注释：

// 单行注释

/*
  多行注释
*/

注释会被跳过，不会进入 Token 序列。

5.5 词法错误

错误 例子 处理方式
非法字符 @ 生成错误 Token，继续扫描。
非法单词 12abc 输出 非法字符(串)。
标识符过长 function1 超过 8 位时报错。
整数过长 123456789 超过 8 位时报错。

6. 递归下降 Parser

相关代码：

src/parser/Parser.h
src/parser/Parser.cpp

入口函数：

bool Parser::parseProgram();

6.1 什么是递归下降

递归下降就是把文法规则翻译成函数。一个非终结符对应一个函数， 函数内部按照文法顺序调用其他函数。

文法单位 代码函数
程序parseProgram()
分程序parseBlock()
常量声明parseConstDecl()
变量声明parseVarDecl()
过程声明parseProcedureDecl()
语句parseStatement()
条件parseCondition()
表达式parseExpression()
项parseTerm()
因子parseFactor()

6.2 Parser 如何读 Token

Parser 不是直接读字符，而是读 Lexer 生成的 Token 列表。

函数 作用
current()查看当前 Token。
advance()消费当前 Token，移动到下一个。
match(type)如果当前 Token 是指定类型，就消费它。
expect(type, message)要求当前 Token 必须是指定类型，否则记录语法错误。

6.3 表达式为什么拆成三层

为了处理优先级，表达式被拆成：

Expression
+ -
→
Term
* /
→
Factor
标识符/数字/括号

例如：

2 + 3 * 4

应该先算 3 * 4，再和 2 相加，所以乘除在 parseTerm() 里处理，加减在 parseExpression() 里处理。

6.4 语法错误

缺少分号、括号不匹配、缺少 do 等错误，主要通过 expect() 发现。

while x < 10
begin
  x := x + 1
end

这里 while 条件后缺少 do，Parser 会报告语法错误行号。

7. 符号表和语义检查

相关代码：

src/semantic/Semantic.h

class SemanticAnalyzer

7.1 什么是语义错误

语法正确不代表程序意思正确。例如：

const a = 10;
begin
  a := 20
end.

这段语法结构没问题，但常量不能被赋值，所以是语义错误。

7.2 符号表保存什么

struct Symbol {
    std::string name;   // 名字
    SymbolKind kind;    // const / var / procedure
    std::string value;  // 常量值
    int level;          // 作用域层次
};

作用域用一个栈保存：

std::vector<std::unordered_map<std::string, Symbol>> scopes_;

可以简单理解为：

全局作用域
→
过程作用域
→
更内层作用域

7.3 当前检查了哪些语义规则

函数 检查内容
declare()同一作用域是否重复声明。
requireAssignable()是否可以作为赋值左值。
requireReadable()read 的参数是否是变量。
requireCallable()call 的目标是否是过程。
requireValue()表达式里的标识符是否能作为值使用。

8. 四元式生成

四元式是中间代码，结构是：

(op, arg1, arg2, result)

代码结构：

struct Quad {
    std::string op;
    std::string arg1;
    std::string arg2;
    std::string result;
};

8.1 赋值表达式

源代码：

c := b + a

可能生成：

(+, b, a, T1)
(:=, T1, _, c)

T1 是临时变量，由 newTemp() 生成。

8.2 if 的跳转

源代码：

if a <= 10 then
  c := b + a

实现思路：

  1. 先判断条件。
  2. 如果条件不成立，跳过 then 语句。
  3. then 语句解析完成后，回填跳转目标。

8.3 while 的跳转

while 会产生一个回跳：

条件开始
→
条件判断
→
循环体
↺

所以四元式中会看到类似：

(j<=, y, 0, $21)
...
(j, _, _, $16)

第一条是条件失败跳出，第二条是循环体结束后跳回条件位置。

9.1 目标代码长什么样

运行：

./cmake-build/pl0c target tests/samples/valid_sample.pl0

会看到类似：

0001  L1:    START
0009         JMP MAIN
0010  L9:    PROC add
0011  L10:   ADD sum x T1
0012  L11:   MOV T1 sum
0015  L14:   RET
0023  MAIN:  NOP
0024  L22:   READ x
0025  L23:   READ y
0034  L32:   CALL countdn
0035  L33:   WRITE sum
0036  L34:   HALT

这些目标指令的含义：

指令 含义
DECL_VAR x声明变量 x。
MOV 10 max把 10 放入 max。
ADD a b T1计算 a + b，结果放入 T1。
JLE y 0 L21如果 y <= 0，跳转到 L21。
CALL add调用过程 add。
RET过程返回。
READ x从标准输入读取一个整数给 x。
WRITE sum输出 sum 的值。

9.2 为什么有 JMP MAIN

四元式里过程体出现在主程序前面。如果直接从上到下执行，会错误地先执行过程体。 所以目标代码生成时会先执行全局声明，然后通过 JMP MAIN 跳过过程定义， 直接进入主程序。

全局声明
→
JMP MAIN
跳过
过程代码
→
MAIN 主程序

9.3 怎么看到运行结果

样例程序中有：

read(x, y);

所以运行时要给两个输入值。例如给 x=1、y=3：

printf '1 3\n' | ./cmake-build/pl0c run tests/samples/valid_sample.pl0

输出：

3
2
1
21

前三行来自过程 countdn，它从 y=3 开始倒着输出到 1。 最后一行 21 是主程序最后输出的 sum。

9.4 解释器内部做了什么

解释器维护几类数据：

数据 作用
变量表保存变量、常量和临时变量的整数值。
标签表把 L16、MAIN 这样的标签映射到目标指令位置。
过程表把过程名映射到 PROC 指令位置。
返回栈CALL 时记录返回位置，RET 时跳回。
程序计数器当前正在执行哪一条目标指令。
这部分答辩很好讲：四元式是中间代码，目标代码是更接近执行的指令序列。 本项目用一个小型解释器执行目标代码，因此可以直接看到 PL/0 程序的运行输出。

10. SLR 语法分析

相关代码：

src/parser/SLRParser.h
src/parser/SLRParser.cpp

9.1 SLR 和递归下降有什么区别

分析方法 理解方式
递归下降 从开始符号出发，按照文法函数向下匹配。
SLR 从输入 Token 出发，用状态栈不断移进和归约。

9.2 产生式

SLR 的文法写在：

std::vector<Production> makeProductions();

例如：

{"Statement", {"while", "Condition", "do", "Statement"}}

表示：

Statement -> while Condition do Statement

9.3 项目和点

LR 项目里有一个点 ·，表示当前读到了产生式的哪个位置。

Statement -> while · Condition do Statement

意思是：已经读到了 while，接下来希望看到 Condition。

9.4 closure 和 goto

函数 作用
closure() 如果点后面是非终结符，就把它的产生式都加入项目集。
gotoItems() 项目集读入一个符号后，点向后移动，再求闭包。

9.5 移进和归约

SLR 运行时维护两个栈：

状态栈 stateStack
符号栈 symbolStack

每一步查 ACTION 表：

动作 含义
移进 Shift读入一个 Token，进入新状态。
归约 Reduce用某个产生式把栈顶符号归约成非终结符。
接受 Accept分析完成，语法正确。
初学者注意：SLR 比递归下降抽象很多。你不需要一次性背下所有项目集。 先能讲清楚“状态栈 + 输入符号查表，决定移进或归约”即可。

11. 可视化导出

11.1 SLR 状态图

命令：

./cmake-build/pl0c lr-dot tests/samples/valid_sample.pl0 > docs/diagrams/slr_states.dot

每个节点是一个项目集，例如 I0、I1。每条边表示读入某个符号后转移到另一个项目集。

11.2 四元式控制流图

命令：

./cmake-build/pl0c ir-dot tests/samples/valid_sample.pl0 > docs/diagrams/ir_cfg.dot

边的含义：

  • 普通四元式：连到下一条。
  • j：无条件跳转，只连到目标。
  • j<rop>：条件跳转，连到目标，也连到下一条。

答辩重点

最后建议：你真正需要讲清楚的是“输入是什么、输出是什么、核心数据结构是什么、错误怎么处理”。 对每个模块都按这四个问题准备，答辩会稳很多。
